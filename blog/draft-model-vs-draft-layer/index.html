A Draft Model or a Draft Layer? How EAGLE Guesses Tokens

Akshith Macharla

In my last post I walked through speculative decoding: a small model guesses the next few tokens, and the big model checks all the guesses in one forward pass. How much that helps comes down to one thing: how cheap the guesses are.

There are two common ways to build the guesser. One is a separate small model. The other is a single extra layer attached to the big model, which is what EAGLE does. This post opens both up and looks at what's inside, with real shapes from Llama 3.1 8B.

One token, start to finish

Before comparing the two, here is what happens when Llama 3.1 8B writes one token:

  1. The last token's ID is looked up in the embedding table, 128,256 rows × 4,096 numbers. Its row, 4,096 numbers, goes into layer 1.
  2. Those numbers pass through 32 decoder layers. Each layer has attention, which looks back at earlier tokens through the KV cache, and an MLP.
  3. Out of layer 32 comes a new list of 4,096 numbers: the model's summary of the whole text so far. People call it the hidden state.
  4. The output head, a 128,256 × 4,096 matrix, turns those 4,096 numbers into 128,256 scores, one per token in the vocabulary.
  5. The sampler picks one token from the scores: the top one for greedy decoding, or a random draw weighted by probability. What comes out is just a token ID.

Three things here are easy to mix up, because two of them are 4,096 numbers long:

What it is Depends on the text so far?
Token ID A single number that names a token No
Embedding The token's row in the embedding table, 4,096 numbers No: the same row every time the token appears
Layer-32 vector What comes out of the last layer, 4,096 numbers Yes: it carries the whole context

Two ways to build the guesser

Both options end the same way: a vector goes through an output head, and the sampler picks a token. What differs is everything before that.

Option 1: a separate small model

The simplest guesser is another, smaller model that uses the same tokenizer. For Llama 3.1 8B, a natural pick is Llama 3.2 1B.

Llama 3.1 8B (target) Llama 3.2 1B (draft)
Layers 32 16
Numbers per token vector 4,096 2,048
Parameters 8.03 billion 1.24 billion
Size in BF16 16 GB 2.5 GB
KV cache per token 128 KiB 32 KiB

It's a complete language model with its own embedding table and output head. It only sees the tokens, so it has to work out what the text means on its own, with a much smaller network than the target.

Four guesses take four passes through all 16 layers, one after another, because each guess depends on the one before. A model this small also wastes time on every pass starting hundreds of tiny GPU jobs, and that can cost more than the actual work. If the draft is slow enough, speculative decoding ends up slower than not using it at all.

The upside is that it needs no training. Any small model with the same tokenizer works out of the box.

Option 2: one extra layer (EAGLE)

EAGLE starts from a simple observation. By the time the target finishes layer 32, its 4,096 numbers already contain the answer; the output head only reads it out. Research on these vectors also shows they carry information about the next few tokens, not just the next one. So instead of a small model learning language from scratch, EAGLE trains one extra layer to take the target's vector and push it one step further.

A walk through with real tokens

Say the text is “The cat sat on the”. The target runs all 32 layers, its output head scores every token, and the sampler picks “ mat”. That's the target's own answer, so it's final and never needs checking.

Now EAGLE guesses what comes after “ mat”. It gets two inputs:

  1. The target's layer-32 vector at “the” (4,096 numbers): the summary of the sentence.
  2. The embedding of “ mat” (4,096 numbers): the row for “ mat” in the target's embedding table.

There are two different “mat” vectors here. The embedding is a fixed lookup with no context. The layer-32 vector for “ mat” would carry the whole sentence, but it doesn't exist yet, because the target hasn't processed “ mat”. That missing vector is exactly what EAGLE tries to predict.

Why is one layer enough? The target has already done the hard part. Its vector at “the” knows there's a cat, that it's sitting, and that a surface comes next. Going from there to “the sentence probably ends after mat” is a small update. A separate small model gets none of that; it starts from the bare words.

What's inside the layer

The layer has three parts, run one after another:

target's layer-32 vector (4,096) + embedding of the last token (4,096)
        = 8,192 numbers
        |
  1. Mixer       8,192 -> 4,096           glues the two inputs into one vector
        |
  2. Attention   looks back at earlier positions through EAGLE's own KV cache
                 (32 query heads and 8 KV heads, like Llama)
        |
  3. MLP         4,096 -> 14,336 -> 4,096  where most of the work happens
        |
  4,096 numbers = EAGLE's guess of the target's layer-32 vector at "mat"
        |
  output head -> a score for every token -> sampler -> "."

Parts 2 and 3 are exactly one Llama decoder layer, the same kind as the 32 inside the target. The only new piece is the mixer at the front. Each part is a few weight matrices, and every guess multiplies through each of them once:

Part Matrix Shape Numbers
Mixer W_mix 8,192 × 4,096 33.6 M
Attention query (Wq) 4,096 × 4,096 16.8 M
Attention key (Wk) 4,096 × 1,024 4.2 M
Attention value (Wv) 4,096 × 1,024 4.2 M
Attention output (Wo) 4,096 × 4,096 16.8 M
MLP gate 4,096 × 14,336 58.7 M
MLP up 4,096 × 14,336 58.7 M
MLP down 14,336 × 4,096 58.7 M
Total ~252 M

That's about 0.5 GB in BF16. The embedding table and the output head are borrowed from the target, not trained. This is the original EAGLE design; EAGLE-3 changes the inputs a little, which the end of this post covers.

Because the layer has attention, it also has a KV cache of its own: 1 layer × 8 KV heads × 128 numbers × 2 (K and V) × 2 bytes = 4 KiB per token, against 128 KiB for the target. When the target rejects a guess, this small cache has to be cleaned up as well.

How it learns

The target stays frozen. Run it over lots of text and record its layer-32 vectors. Then train only the new layer: given the vector at one position and the next token's embedding, its output should make the output head pick the same token the target would pick next. The weights start random and get adjusted over millions of positions.

That's also the catch: an EAGLE layer is trained for one specific target model. You can't take one made for Llama 3.1 8B and use it with Qwen3-8B.

One full round

1. Target pass                 -> real token " mat" (final, no check needed)

2. EAGLE pass 1: [target's vector at "the"] + [embedding of " mat"]  -> "."
   EAGLE pass 2: [EAGLE's vector at "mat"]  + [embedding of "."]     -> " The"
   EAGLE pass 3: [EAGLE's vector at "."]    + [embedding of " The"]  -> " dog"
   EAGLE pass 4: [EAGLE's vector at "The"]  + [embedding of " dog"]  -> " barked"

3. Target pass on [" mat", ".", " The", " dog", " barked"]
   -> checks all four guesses at once

4. Keep the guesses that match, take the target's own token at the
   first miss, and start again.

Two details matter here. Only the first EAGLE pass starts from the target's real vector; after that, EAGLE builds on its own guessed vectors, so later guesses are less accurate. And “ mat” goes into the next target pass not to be checked again, but so the target can compute its real layer-32 vector and write its keys and values into the KV cache.

So a round with four guesses costs four EAGLE passes, one after another, and one target pass.

The part that surprised me: the output head

Every EAGLE guess still goes through an output head to become a token. Here's what one guess reads from memory:

Per guess Bytes read (BF16)
EAGLE layer ~0.5 GB
Target's output head (128,256 × 4,096) ~1.05 GB
Total per EAGLE guess ~1.55 GB
For comparison: all of Llama 3.2 1B ~2.5 GB

The output head costs twice as much as the EAGLE layer itself. In bytes, an EAGLE guess isn't dramatically cheaper than a small draft model. So where does the speedup come from?

  1. One layer instead of sixteen. Far fewer tiny GPU jobs to start per guess, and for one user that start-up cost is what really slows a small model down.
  2. Better guesses. Starting from the target's own vector means more of them get accepted per round.

EAGLE-3 goes after the output head directly. Its draft gets its own, smaller output head that only scores the 32,000 most common tokens: 32,000 × 4,096 numbers, about 0.26 GB, four times smaller. If the right token isn't in that list, the guess is simply wrong, and the target catches it.

Is it worth it?

Usually, yes. SGLang's docs show Llama 3.1 8B on one H100, serving one user at a time, going from 158 tokens/s with plain decoding to 373 tokens/s with EAGLE-3.

Separate small model EAGLE layer
What it reads Only the tokens The tokens + the target's layer-32 vector
New weights A whole model (1.24 B for Llama 3.2 1B) ~250 M
Layers per guess 16 1
Its own KV cache 32 KiB per token 4 KiB per token
Training None Trained for one target model
Works on its own Yes No, it needs the target running

The small model still has a place: it needs no training, and it doesn't care what kind of text you give it. An EAGLE layer trained on chat data can guess worse on code, which is why Amazon SageMaker offers to train one on your own data.

How many tokens should it guess?

The number of guesses per round, k, is a setting. There's no hard limit, but each extra guess costs more and is worth less: it's one more EAGLE pass, and it only counts if every guess before it was right. If each guess is right 75% of the time:

k (guesses) Tokens per round, on average
2 2.31
4 3.05
8 3.70
No limit 4.00 at most

Going from 4 guesses to 8 doubles the drafting work but adds only about 0.65 tokens per round. In practice, MAX defaults to 2 guesses for EAGLE, and SGLang picks 3 to 5 on its own. In AWS's tests, EAGLE-3 did best at 3 guesses.

Where EAGLE went next

  • EAGLE-2 guesses a tree instead of a single line. At each step it keeps the top few candidates, grows the branches it's most confident about, and the target checks the whole tree in one pass.
  • EAGLE-3 reads the target's vectors from a low, a middle and a high layer instead of only the last one. It predicts tokens directly, gets its own small output head, and is trained on its own guesses, the same way it's used.
  • P-EAGLE and DFlash remove the four-passes-in-a-row problem. They guess all the tokens in one pass, so more guesses cost almost nothing extra. P-EAGLE did best at 7 guesses in AWS's tests, compared with 3 for EAGLE-3.

Takeaways

  • A guesser can be a whole small model or a single extra layer. EAGLE is the second.
  • EAGLE's layer reads two things: the target's layer-32 vector, which carries the context, and the last token's embedding, which says which token was picked.
  • It's one ordinary decoder layer plus a mixer. About 250 million new numbers, with a tiny KV cache of its own.
  • The output head is the biggest cost per guess. EAGLE wins because it runs one layer instead of many, and because more of its guesses are right.
  • More guesses aren't free. Cheaper guesses let you afford more of them, which is where P-EAGLE and DFlash come in.
